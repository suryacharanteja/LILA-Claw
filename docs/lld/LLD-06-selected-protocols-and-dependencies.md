# LLD-06 — Selected protocols and dependencies

Version: 0.2  
Status: Approved within LLD v0.2 — see ../approval-records/LLD-v0.2-approval.md
Date: 7 September 2026

This chapter closes the design choices formerly labeled G-01–G-05. It is normative over candidate/open-choice wording in v0.1. Documentation establishes available interfaces; integration/security tests remain mandatory build acceptance, not claims of completed validation.

## Selected implementation stack

| Concern | Selection / rule |
|---|---|
| Runtime | CPython 3.12 x64, regular GIL build; pin latest available security patch within 3.12 in build lock |
| Coordinator | FastAPI, Pydantic v2, Uvicorn single process; SQLCipher writer thread serializes transactions; no multi-worker Uvicorn |
| HTTP | httpx clients with TLS verification, explicit timeouts and redirects disabled for authenticated local/provider requests |
| Database | sqlcipher3 0.6.2 CPython 3.12 win_amd64 wheel; SQLCipher 4-compatible encrypted storage, raw 32-byte random key |
| Crypto/Windows | cryptography AESGCM, HKDF(SHA256), HMAC/SHA256, Ed25519 and X.509 APIs; pywin32 for DPAPI, ACLs, named pipes/mutexes and certificate-store integration |
| Worker | LangGraph 1.2.10 with the compatible langgraph-checkpoint dependency resolved and hash-locked; async BaseCheckpointSaver adapter, no DeltaChannel or arbitrary checkpoint deserialization |
| AI | OpenAI Responses HTTPS API through httpx; model snapshot gpt-4.1-mini-2025-04-14; JSON-schema outputs, no provider tools or silent fallback |
| Web | React 19, TypeScript 5, Vite, React Router, TanStack Query; npm lock committed; build-time Node LTS only |
| Extension | Manifest V3 TypeScript, chrome.debugger, chrome.storage.local trusted contexts, packaged deterministic content-script functions; no remote code |
| Documents | python-docx for DOCX creation/extraction, pypdf for text PDF extraction, fpdf2 for generated PDF; scanned/image-only input receives manual fact entry |
| Packaging | PyInstaller onedir and Inno Setup 6 per-user installer; Authenticode-signed EXEs/installers plus Ed25519 signed release manifests |
| Tests | pytest, httpx ASGI tests, browser fixture tests and Windows/Chrome integration harness; Playwright may drive test fixtures only, not act as production browser controller |

All direct/transitive versions and artifact hashes are captured in requirements.lock and package-lock.json in milestone M0; the lock is a build output, not a guessed current dependency resolution. No production dependency may float at installation. If the resolver cannot satisfy this selected stack, report the incompatible component and amend LLD; do not silently swap architecture. Retain MIT notices for reused local source and inventory all bundled component licenses.

SQLCipher wheel existence and hash were verified in [the package release](https://pypi.org/project/sqlcipher3/): sqlcipher3-0.6.2-cp312-cp312-win_amd64.whl, SHA256 8bd60ffb7bfa65bd0e51da3d5c308553d7149f0091d4ea9f754c33d5ebbf0a66. Build acceptance still verifies loaded cipher_version and actual encryption. PyInstaller onedir is documented in [its usage guide](https://pyinstaller.org/en/stable/usage.html); per-user non-elevated installation is supported by [Inno Setup PrivilegesRequired=lowest](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm).

## G-01 closure: loopback TLS and explicit pairing

Use HTTPS/WSS on 127.0.0.1:43127, falling back to a dynamically assigned loopback port if occupied. Launcher obtains the selected port from its authenticated local control pipe, never by trusting the occupant of a port. Host validation accepts only the actual 127.0.0.1 host:port; reject alternate hostnames and DNS rebinding. HTTP is not served as a downgrade route. This instantiates the approved HTTP/WebSocket protocols over TLS.

During explicit first-run setup, generate an installation-specific local CA and server leaf with cryptography. CA: RSA-3072, SHA256 signature, CA=true, path_length=0, keyCertSign/crlSign only; critical name constraints restrict DNS to localhost and IP to 127.0.0.1/32 and ::1/128. Leaf: RSA-3072, serverAuth EKU, SAN localhost/127.0.0.1/::1, CA=false, 90-day validity. CA has five-year validity, random serial, installation UUID in display name. Store both private keys DPAPI-protected with owner-only ACL. Install only this CA's public certificate in CurrentUser Root after a clear setup confirmation; never modify LocalMachine trust or disable Chrome certificate checks. Scope/cleanup is recorded by certificate thumbprint. Renewal at 30 days remaining uses existing CA, server key and normal trusted launch; a new CA requires the explicit setup flow again.

Chrome considers local trust entries ([Chromium certificate FAQ](https://chromium.googlesource.com/chromium/src/+/main/net/data/ssl/chrome_root_store/faq.md)). Validate the constrained CA on actual supported Chrome/Windows builds in M1. If local policy denies trust installation, report setup unsupported and stop; no insecure bypass. This is a disclosed new installation detail for LLD review, not a certificate installed during documentation work. Same-user administrative/malware compromise is outside this trust guarantee.

Worker and launcher pin the installation leaf SPKI and trust chain using their protected configuration. Extension pins an application Ed25519 identity public key supplied in the pairing code; browser TLS supplies the UI's server authentication. Persist server identity and credential_epoch separately from business backups.

### Launcher control and browser session

Named pipe \\.\pipe\LILAClaw-{userSID}-{installID}, local-only with owner SID/SYSTEM ACL, reject remote clients; verify connecting process user SID. Pipe commands limited to launch URL, status, quit and worker boot handoff. No Native Messaging host or browser-native bridge is registered.

Trusted launcher requests a random 32-byte one-use UI bootstrap token over the pipe, expires after 60 seconds. Open https://127.0.0.1:{port}/#bootstrap={base64url-token}; fragment is removed by history.replaceState before any other navigation. Page has no third-party assets and Referrer-Policy:no-referrer. POST token once to /api/v1/auth/bootstrap over TLS; consume atomically and set HttpOnly Secure SameSite=Strict host-only cookie __Host-lila-session, Path=/, Max-Age=86400. Token never appears in query, server access log or Referer.

Store token/session hashes (HMAC with protected server key) in a separate encrypted auth store, not business backups. Browser session expires after 24 hours; renewable while unrevoked via same-origin authenticated renewal. Renewal rotates session secret with a 30-second overlap for concurrent tabs; old secret cannot renew twice. A closed/expired session can be reopened through launcher; it does not pause otherwise authorized background work. Do not persist bearer secrets in JS storage.

State-changing UI requests require exact Origin and X-Lila-CSRF header. GET /api/v1/auth/session issues session-bound random CSRF token over same-origin authenticated TLS. Cross-origin reads get no CORS allowance. CSP default-src 'self'; script-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'none'; connect-src 'self'; no inline/eval script. API Cache-Control:no-store. SSE uses the cookie with same-origin Origin/Fetch-Metadata validation; never tokens in URLs.

### Extension pairing and renewal

Launcher displays a one-time pairing code containing version, install_id, port, pairing_id, server Ed25519 public key and random 32-byte pairing secret S. Code expires in 5 minutes; maximum 5 failed proof attempts. Copy/paste into extension options is sufficient; QR optional, not required. Extension connects WSS with configured extension-ID Origin allowed only for pairing/auth routes. Development extension ID is explicit developer configuration; production ID comes from the signed release manifest.

Server sends nonce Ns; extension generates Nc and proves HMAC-SHA256(S, UTF8('lila-pair-v1') || pairing_id || Ns || Nc). Transcript fields use length-prefixed byte encoding. Server proves Ed25519 signature over SHA256(the same transcript || client-proof). Extension verifies against pinned public key before accepting credentials. Server records pending peer identity; owner confirms it in authenticated admin UI; only then atomic consume pairing and issue a random 32-byte renewable extension credential scoped to browser execution/status/controls. Any expired/mismatched/replayed transcript is rejected.

Store extension credential in chrome.storage.local with TRUSTED_CONTEXTS access; retain pinned public identity. On reconnect use nonce challenge HMAC with that credential and server signed challenge; no bare credential in WebSocket URL. Session expires in 15 minutes, renew 2 minutes before expiry over the authenticated connection without altering action policies. Close active sessions on revocation; credential_epoch changes invalidate all previous sessions and challenge material. Rate-limit auth failures per peer/install (5/minute), retain no entered secret in logs. TLS and nonce proof protect transmission/replay; they do not make compromised extension storage a secure vault.

### Worker boot

Supervisor creates an anonymous inherited pipe restricted to the spawned worker handle set. Deliver {worker_id,generation,port,server_spki_pin,random_32_byte_token} once through that pipe. Keep tokens in memory only; never argv/env/checkpoints. Worker uses pinned HTTPS Authorization: Bearer with internal route scopes and generation checks. Token lifetime ends at worker termination/fencing; supervisor passes coordinator registration through its authenticated control channel. Termination fences tokens before spawning replacement.

## G-02 closure: encryption and formats

Initialize SQLCipher before any schema read: supply random 32-byte raw key using the driver's key interface/hex PRAGMA without SQL tracing, check cipher_version, require cipher_compatibility=4, foreign_keys=ON, journal_mode=WAL, synchronous=FULL, temp_store=MEMORY, busy_timeout=5000. Run cipher_integrity_check plus integrity_check on qualification/restore; ordinary connection opening performs a key-verifying schema read. Check encrypted WAL/journal behavior with plaintext canaries. Use online backup into an explicitly keyed destination; never assume driver backup automatically preserves encryption. API settings are documented in [SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/index.html).

Keys: install-local random Kdb (32 bytes), Kartifact-wrap (32), Kaudit (32), Kauth (32), Kidentity private; each stored as DPAPI-protected owner ACL secret with key_id. Authentication store and business DB use different keys. Generate one random 32-byte DEK per artifact and wrap it using AES-256-GCM under Kartifact-wrap with fresh random 12-byte nonce; AAD identifies format/key/object/version. Random recovery key Kr (32 bytes) is presented as unpadded base64url plus the first 8 bytes of SHA256(Kr) encoded as 16 hex characters; no human-password KDF is needed because it is high entropy. Local DPAPI copy of Kr permits unattended backups; owner keeps an independent copy. Keys are excluded from ordinary JSON/CSV/export metadata.

Artifact binary format LILAOBJ1: 8-byte ASCII magic; uint32 big-endian header length; UTF-8 canonical JSON header; AESGCM ciphertext including 16-byte tag. Header <=4096 bytes: {format:1,object_id,version_id,key_id,nonce_b64,plaintext_length,media_type}; entire magic/length/header is AAD. Nonce random 12 bytes, unique per object DEK; retry re-encryption generates a new DEK/nonce. Maximum plaintext object 100 MiB; larger uploads get a visible limit, adjustable only with tested resource bounds. Use cryptography AESGCM, never accept tag failure or fall back to plaintext. See [authenticated-encryption API](https://cryptography.io/en/latest/hazmat/primitives/aead/).

Portable LILABAK1 container: magic, bounded canonical JSON header, then indexed encrypted chunks. Generate random package key Kp and random 8-byte nonce prefix. Wrap Kp under Kr using AESGCM and random 12-byte nonce with backup_id/format as AAD. Header carries wrapped Kp, wrapping nonce, backup_id, schema_version and chunk size 4 MiB. Chunk nonce = 8-byte prefix || uint32 big-endian chunk index; never reuse prefix/Kp; fewer than 2^32 chunks. AAD = SHA256(header bytes) || index || final_flag. Encrypt a logical stream of length-prefixed entries (manifest, keyed DB snapshot plus recovery-wrapped Kdb for that snapshot, artifacts with necessary recovery-wrapped DEKs, audit verification keys/boundaries). Internal manifests and keys are encrypted; API/Telegram/pairing/authentication keys never enter the container. A final authenticated chunk records stream digest and total chunk count; reject truncation, duplicate/reordered chunks, trailing bytes, oversized entries and path traversal. Recovery data-encryption keys are distinct from excluded authentication credentials. Extract only opaque managed object IDs, not archive filenames.

New-profile restore unwraps with Kr, validates snapshot, then rekeys database and rewraps artifact DEKs using newly generated local keys before activation. Preserve old audit verification key material only as encrypted business recovery data needed to verify the old journal; use new audit generation for subsequent events. Never activate old auth-store files.

Canonical application JSON: UTF-8, keys sorted by Unicode code-point, no insignificant whitespace, no floats/NaN, NFC-normalized strings before encoding, integers limited to signed 64-bit, no duplicate keys, null/bool allowed. Format is project-defined for its restricted types; do not claim general RFC canonicalization compatibility. Hash versioned payload bytes with SHA256. Keep hashes of personal values inside encrypted storage; no public guessable identity hashes.

Audit event authenticator = HMAC-SHA256(Kaudit-generation, domain separator || generation || sequence || previous_tag || canonical_event). Segment every 1000 events or UTC day boundary, whichever first; seal segment with first/last sequence and tag and link the next segment. Authenticated retirement record preserves boundaries before an expired segment is removed. Mutable checkpoint storage is not the audit authority. Local rollback of DB+keys may be undetectable; no external anchor is introduced.

Rotate local data keys on explicit recovery/security reset and otherwise annually: stage rekey, verify, atomically switch active generation, retain old encrypted keys only while referenced; never delete before restore proof. Portable recovery-key rotation generates new backups, warns which older copies require the old key, and does not pretend detached copies were reencrypted. Certificate/key expiration and retention are separate lifecycles.

## G-03 closure: checkpoint and provider

Subclass BaseCheckpointSaver; implement get_tuple/list/put/put_writes/delete_thread and async aget_tuple/alist/aput/aput_writes/adelete_thread. Async worker uses async methods; sync wrappers use a separate blocking HTTP client, never nested event-loop calls. Source interface: [LangGraph checkpoint base](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint/langgraph/checkpoint/base/__init__.py). Lock the resolved checkpoint package and run conformance against its installed signatures in M0; unsupported DeltaChannel/copy/prune operations explicitly raise NotImplementedError and are never used by the graph.

thread_id=run_id; checkpoint_ns identifies graph namespace; checkpoint_id selected by LangGraph. put returns configurable {thread_id,checkpoint_ns,checkpoint_id}; get_tuple returns checkpoint, metadata, parent_config and pending_writes. Store new_versions and all channel_values/versions_seen. put_writes key=(run,namespace,checkpoint,task_id,write_idx); use installed WRITES_IDX_MAP for special channels and positional index otherwise; preserve special-channel update semantics and normal-write idempotency. Persist task_path. list sorts checkpoint IDs descending and implements before/limit plus equality metadata filters. deletion is coordinator privacy operation; worker cannot delete arbitrary runs.

Serializer accepts only JSON values plus explicitly tagged bytes/base64 and known interrupt metadata; application graph state contains IDs and JSON records, not Python objects. No pickle, arbitrary import or permissive object reconstruction. get_next_version generates strictly increasing integer channel versions; no experimental channel types. Checkpoint writes use stable command identities and generation fencing; a graph node calls coordinator ensure_action(logical_step_key) rather than minting new actions on replay.

Initial model is a deliberately bounded drafting/classification implementation target, not a claim of best current model. Pin gpt-4.1-mini-2025-04-14, which supports structured outputs ([model reference](https://developers.openai.com/api/docs/models/gpt-4.1-mini)). HTTPS POST https://api.openai.com/v1/responses; Authorization bearer credential from worker boot-authorized secret fetch; store:false; no conversations, file upload, built-in tools, background mode, or previous_response_id. Input only verified necessary facts, job excerpts and a fixed instruction; max_output_tokens=2048, temperature=0, text.format strict json_schema. Detect refusal/incomplete status before decoding; validate JSON and factual references after decoding. See [structured output contract](https://developers.openai.com/api/docs/guides/structured-outputs). store:false is not a guarantee of zero provider retention; explain provider data controls during setup ([data controls](https://developers.openai.com/api/docs/guides/your-data)).

Timeouts: connect 10s, overall read 60s; no automatic SDK retry (direct httpx). One explicit retry only for a confirmed rejected/not-processed request under remaining budget; timeout/ambiguous 5xx keeps reservation and asks for reconciliation rather than replaying paid requests silently. One schema-repair generation allowed under a separate reservation; it cannot invent missing facts. No fixed provider data is sent until owner configures/enables provider use.

Pricing seed at review: USD 0.40/1M input and 1.60/1M output; reserve uncached price. Provider config contains checked_at and exact model/rates; revalidate at build and require owner confirmation when price data older than 30 days before hard-budget work. For initial hard bound reserve the configured max request input cap (32,768 tokens) plus output cap; tokenizer estimate is display only, not the hard-bound proof. Reject provider configuration whose total possible input cannot be bounded by the application payload limit/model tokenizer test. Smaller accurate bounds may be used after token-count contract tests. Accumulate internal integer micro-USD, round up only at displayed minor-unit boundaries; this refines the prior minor-unit-only draft to avoid excessive rounding per call.

## G-04 closure: deterministic browser adapter

Production execution uses chrome.debugger plus packaged content-script functions only. DOM/Accessibility inspection locates a unique visible eligible element; dispatch input through approved CDP calls. Runtime.evaluate/callFunctionOn is allowed only for fixed packaged function bodies with typed escaped arguments, never model-generated JavaScript or arbitrary selectors. This clarifies the earlier generic-eval prohibition: no public generic eval tool exists.

Search adapter: validate www.linkedin.com/jobs/search or /jobs/view/{numeric_id}; normalize IDs from canonical job URLs. Read accessible labels/roles and list-card job links. Query controls must have one unambiguous semantic match; missing/ambiguous controls produce UNSUPPORTED_VARIANT. Native filter not available may be explicitly reported post-filtering of retrieved facts under FD-002; never guess a hidden URL parameter.

Application adapter operates only a visible active application dialog for the selected job, identified by heading/job context and a unique known step. Discover label-control relationships using label[for], aria-labelledby/aria-label, input type, required flags and rendered options. Only supported field meanings in the catalog map to verified facts. Before each mutating action compute SHA256 of normalized step heading, ordered field labels/types/options, job ID and account context; reinspection mismatch causes replan/review. Fixed control roles/names support English UI first; other languages hand off with explicit unsupported reason pending adapter addition. This is a disclosed qualification scope, not a claim every English variant works.

Upload: coordinator issues action-bound capability to an already decrypted restricted temporary file. Extension requests the absolute path over authenticated WSS only after capability validation; verifies target file input belongs to expected dialog; uses DOM.setFileInputFiles, then observes accepted filename/error. No arbitrary worker path. API: [CDP DOM](https://chromedevtools.github.io/devtools-protocol/tot/DOM/#method-setFileInputFiles). Keep temp file until upload consumption/error reconciliation (maximum 10 minutes), then delete; coordinator restart cleans orphaned upload temps after fencing old action ownership.

Submission positive evidence: a validated completion message in the application flow tied to the active job, or an independently observed applied status for that same job after submission. Capture normalized evidence text/context/time and minimal permitted screenshot if enabled. Absence of dialog/button alone is UNCERTAIN. Negative evidence (validation error and no submit transition) can establish NOT_SUBMITTED; network failure cannot. Capture a successful and negative fixture for each enabled variant during authorized implementation qualification. The LLD specifies selector strategy and semantic rules; fixture values are test data collected during build, never invented in this document.

## G-05 closure: installer, signed updates and trust inputs

PyInstaller onedir, UPX disabled, one executable with --role launcher/coordinator/worker and explicit role-specific entry checks; supervisor spawns child processes with restricted inherited handles. Inno Setup 6: PrivilegesRequired=lowest, DefaultDirName={localappdata}\\Programs\\LILAClaw, app data separately under {localappdata}\\LILAClaw. HKCU Run entry added only on explicit startup setting. Use a Win32 job object for child cleanup; intentional stop marker and generation fencing precede process termination.

Release manifest canonical JSON signed Ed25519 with an offline release key; client embeds public key and key_id in its trusted installed build. Sign exact canonical bytes excluding signature field. All EXEs/installers additionally Authenticode signed; verify using WinVerifyTrust with signer and timestamp checks. HTTPS feed URL, public key, certificate thumbprint and production extension ID are release-owner provisioning inputs in release-inputs.json, not architecture TBDs. Production build fails if these are empty/test values. Development build supports local synthetic feed/test key with a prominent Development indicator and cannot publish stable-channel artifacts.

Update key rotation requires a transition manifest signed by both old and new keys, monotonically increasing release sequence and expiry; reject downgrade/replayed sequence below protected installed high-water mark. Do not delete older high-water state through business restore. Download host allowlist from signed config; no redirects to unlisted origins. Max download 1 GiB, SHA256 verification, trusted Ed25519 signature and Authenticode validation before execution.

Updater journal {operation_id,old_version,new_version,old_store,new_store,phase} is DPAPI-authenticated and atomically replaced. New version and compatible migrated store are staged together; active.json selects the pair using same-volume ReplaceFile semantics. Health failure before external dispatch can revert the staged pair; once new version has dispatched, rollback requires explicit recovery/reconciliation rather than blind snapshot restoration. Keep old pair until a completed verification and successful backup; obey disk/retention exceptions visibly. On uninstall, remove only this install's recorded public CA thumbprint and startup registration; preserve encrypted business data by default, and re-establish certificate trust on reinstall. Deleting personal data additionally removes its local keys after explicit preview, with detached-backup consequences shown. No secrets or real signing credentials are created by this specification.
